# 29 · 看板视觉重构（v1.9，参考 refero「Ui — clinical blueprint on frosted paper」）

> 用户提供设计参考：<https://styles.refero.design/style/0fd67ec5-7e9c-4ca9-b368-5d9c7388477a>
> （shadcn/ui 风格：单色、纸面卡片、24px 容器圆角、18px 胶囊、发丝线、极轻投影、紧凑字阶）。
> 目标：把「任务看板」从工具化表格外观升级为可读、有层次、有视觉节奏的仪表盘，同时保持深浅色主题适配。

## 1. 设计映射（参考 → 本插件）

| 参考规范 | 实现 |
| --- | --- |
| Canvas/Surface/Paper 三层表面 | `.atw-root` 用 `--atw-canvas/--atw-paper/--atw-surface`，全部取自宿主 `--dsw-alias-*` token，深色主题自动成立 |
| Card 24px 圆角 + 1px 发丝线 + 极轻投影 | `.atw-panel`/`.atw-member`/`.atw-drawer`：`border-radius:24px`、1px hairline、三层 `color-mix` 阴影 |
| 交互元素 18px 胶囊 | `.atw-btn`/`.atw-badge`/`.atw-filter`/`.atw-node`：`border-radius:18px`，按钮统一 36px 高 |
| 紧凑字阶（12/14/16/24/30） | 标题 30px/600/-0.025em；正文 14px/1.43；caption 12px/1.33、0.05em 大写 |
| Stat block（大数字+小标签） | 新增 `.atw-stats`（已批准 / 参与者 / 待处理 三块），数字 30px/600 tabular-nums |
| Pill badge（soft） | `.atw-badge` 默认 soft 填充；状态色用 `color-mix` 着色，红色仅用于错误/阻塞 |
| 唯一主操作（深色填充按钮） | 刷新 = `atw-btn--primary`（ink 填充）；暂停 = ghost；其余 outline/ghost |
| 嵌套卡片 10px | 流程图卡片、频道行、提案卡、事件行等嵌套容器统一 10px |
| 留白节奏 | 页面 padding 24/28、栅格 gap 20、卡片 padding 20、统计块 padding 14/22 |

## 2. 结构变化

- **顶部 hero**：30px 标题 + 目标摘要（2 行截断）+ 三格统计块（已批准数/参与者/待处理）+ 右侧状态徽章/进度条/按钮；
- **主栅格**：流程图 2fr + 拓扑 1.4fr；下方频道 2fr + 提案/用量；1180px 以下单列；
- **流程图**：卡片放大到 208×152（无 Git 行 132），悬停轻微上浮，待评审用 warn 内描边，选中用 brand 内描边；
- **协作拓扑**：画布改为 surface 底 + 18px 圆角；Lead 节点改为 ink 填充胶囊，成员/工作项保持 paper 胶囊；
- **频道/提案/事件**：嵌套纸面卡片，时间戳 caption 右对齐，过滤按钮为胶囊；
- **空态**：面板内空态统一为虚线圆角卡 + 居中 muted 文案；
- **抽屉**：成员/工作项抽屉 24px 圆角 + 强一点的浮层阴影，私聊输入为胶囊填充；
- **动效**：120-200ms 过渡 + 运行节点脉冲；`prefers-reduced-motion` 全部降级；
- **响应式**：720px 以下收窄 padding、标题降为 24px、统计块紧凑。

## 2.1 协作拓扑重构（v1.9.1，本轮重点）

旧布局的问题：成员和工单各自均匀散布，成员→工单项的连线横穿画布；左侧「成员/工作项」标签压在节点上；条目多时连线像一团乱麻。

新布局：
- **按负责人分列**：每个工单放在其 owner 的正下方（同 owner 的第 2 个起放到下一行，再溢出则在本列 ±4% 内错位），owner→item 连线变成短竖线；
- **Lead 反色胶囊**居中在顶部，成员按单行/双行（>6 人）均分在中间带，间距收紧并留出 15% 左右边距，节点不再被画布裁切；
- **频道/评审边**：评审边保持虚线 + 箭头，Lead 边弱化；同伴边只保留 top-8 并加权；
- **箭头标记**：新增 SVG marker，owner/review/lead 边带方向箭头，逻辑一眼可见；
- **区域标签**：「成员」「工作项 · 按负责人对齐」固定在左上方空白处（不再压住节点）；
- **画布增高到 300px**，拓扑面板独立 440px 高度带（其它面板仍 240–320px）；
- **契约测试新增**：owner 列对齐、第二行错位、所有节点 left ∈ [3,97] 不越界。

## 2.2 密集场景再优化（v1.9.2）

用户实测 9 人规模时仍显拥挤，问题在于**拓扑被挤在 1.4fr 窄列**、9 条 Lead 曲线在窄画布里交叉、空闲节点压在连线上、工单标签过窄。

- **拓扑独占整行**：`.atw-main` 改为单列，流程图与拓扑各占满宽（约 1100px），成员/工单获得横向空间；小屏依旧是单列；
- **Lead 组织树总线**：不再画 9 条从 Lead 到成员的曲线，而是「垂直主干 + 每行一条水平总线 + 每个成员一段短竖线（带箭头）」，像组织架构图，多行成员也只多一条总线；
- **成员两行**：>6 名参与者自动两行（10%–90% 边距），9 人时每行 5/4，胶囊不重叠、不被裁切；
- **空闲节点移到右上角**（x=92%, y=10%）：不再压住 owner/review 连线，鼠标悬停仍可看到名单；
- **评审边改为弧线**：`Q` 贝塞尔外扩 7%，与 owner 竖线分离；
- **工单宽度自适应**：`maxWidth = clamp(10%, 18%, 86% / 工单数)`，9 个工单时仍能看清 `I1…I9`；
- 布局预览（同源 CSS + 同一几何算法渲染的 9 成员 × 9 工单）：`docs/evidence/dashboard/topology-dense-preview.png`；
- v1.9.3 后同一用例（无同伴弧线、评审车道、同伴消息胶囊）：`docs/evidence/dashboard/topology-dense-preview.png` 已覆盖。

## 2.3 去线化再优化（v1.9.3）

用户反馈 v1.9.2 仍有「线太多」：同伴弧线（橙色）横穿成员胶囊、评审虚线长斜线互相交叉、空缺填充让画布显得空。

- **同伴关系移出画布**：不再画 peer 弧线，改为图例下的「同伴消息」胶囊条（top-3，按消息量排序，`m2 ↔ m3 · 12`），悬停可看 kinds；Lead 边随之不再需要弱化也能读清；
- **评审关系改直角车道**：`评审人 ↓ → 公共车道(62%) → 工作项 ↓`，虚线只走一条水平车道，不再斜穿成员胶囊；
- **Lead 组织树总线**（v1.9.2 引入）+ **工单 owner 分列**保持；
- **画布高度随成员行数自适应**：单行 250px、双行 310px，不再留大片空白；
- 区域标签下移避开评审车道；画布内只保留「Lead 总线 + owner 竖线 + 评审车道」三类线，信息层级从「图」转为「图 + 摘要」。

## 2.4 评审也去线化（v1.9.4）

v1.9.3 之后画布只剩 Lead 总线、owner 竖线、评审车道三类线；但 3 人用例里「rev-hello 审 W1 & W2」仍会拉出一条横贯全宽的虚线车道，压在区域标签上。

- **评审关系改为工单角标**：工作项胶囊内显示 `评 rev-hello`（多人显示 `评 ×N`），画布不再画评审线；图例下加一行 `工作项角标 = 评审人` 说明，悬停 title 仍给出完整评审人列表；
- **工单槽位去重**：双行成员（>6 人）时，两行可能共享同一 x 列（如 m1 与 m6 都在 10%），原算法会让两个工单叠在同一坐标；现在按「列 + 第一空行带」落位，一列最多 2 个工单（72% / 85%），超出再横向微移；
- **工单宽度**提升到 `clamp(14%, 20%, 86% / 工单数)`，容得下 ID + 评审角标；
- 画布最终只剩两类连线：**Lead 组织树**与 **owner→工单竖线**，视觉噪音最低。

## 2.5 自适应布局（v1.10.0，真正随人数伸缩）

绝对坐标 + 固定行带在 8 人/10 工单时必然重叠或裁切（v1.9.x 的残影：pill 互相覆盖、工单被挤到同一点）。这一版把拓扑从「坐标图」改成「响应式列」：

- **成员 = 自适应列**：`display:flex; flex-wrap:wrap` 的 `.atw-topo-grid`，每列 `flex:0 1 210px; min-width:160px`；8 人时自动换行成 5+4，任意人数都不会重叠、不会被右边界裁切，浏览器宽度变化也自动重排；
- **工单 = 列内子项**：每个成员的负责项渲染在其列内（`flex-direction:column`），归属关系由「包含」表达，不再需要任何 owner 连线；
- **评审 = 工单角标**：`评 rev-hello` / `评 ×2` 仍在 chip 内，多评审人可悬停看全名；
- **无归属项**：unassigned items 进入底部「待认领」横条，不混入成员列；
- **Zero 连线**：画布不再有 SVG/坐标/绝对定位。Lead 与成员、成员与工单的关系由层级（Lead row → 成员列 → 工单 chip）和列内嵌套表达；
- **画布高度自动**：`.atw-topo-canvas{height:auto}`，行数多就自然变高，面板 `max-height:640px` 内部滚动；
- **移动端**：列自然堆叠为 2 列/1 列，无需专门断点；
- **契约测试**：37 例，其中 2 例改为「工单必须出现在 owner 列内且不串列」「9 人 9 工单每项恰好出现一次，列数=9」。

## 2.6 执行流程图缩放/平移（v1.11.0）

11 个工作项的流程图会超出面板宽度，右列卡片被裁掉，且没有任何缩放手段。这一版给流程图加「可看全」能力：

- **缩放控件**：面板头右侧 `− / 100% / + / 适应宽度 / 100%`，范围 40%–160%；数字用 `aria-live` 播报；
- **自动适应（首次）**：某 run 首次渲染时测量画布宽度，若超出视口则自动缩到适应宽度（只做一次，不抢用户后续缩放）；
- **拖动平移**：画布容器 `cursor:grab`，按住拖动即可平移（`pointerdown/move/up` 直接改 scrollLeft/Top），不依赖滚动条；
- **CSS `zoom` 而非 transform**：滚动区域尺寸随缩放一起变化，滚动条始终真实：`zoom` 在 Chromium 下参与布局，这是「看全」的关键；
- **移除评审回路箭头**：原来每个经过评审的卡片右侧画 `R1/2` 虚线弧 + 长对角线，11 张卡时是最主要的视觉噪音；评审轮次卡片内已有「评审 1/2」文本，故删除回路箭头/标签；
- 画布仍保留「波次列 + 依赖边 + 卡片」，横向/纵向滚动由 `.atw-flow-scroll` 承担。

证据：真实 Host 截图 `docs/evidence/dashboard/flow-zoom-live.png`（控件、100%、无回路箭头、自适应拓扑同屏）。

## 2.7 关系可视化：从「线」改为「显式关系」（v1.12.0）

执行流程图里唯一剩下的线是「依赖箭头」：11 张卡时从上游卡片画到下游卡片的长曲线必然穿卡、互交。这一版把关系从「让用户顺着线找」改成「直接写清楚」：

- **卡片自述关系**：每张卡新增一行关系 chip：`依赖 W1`（blockedBy）与 `解锁 W4 · W5`（由本项解阻塞的下游项），一眼知道上下游；
- **关系摘要条**：流程图底部新增两行
  - `依赖链  W1 → W4  W3 → W5`（按 blockedBy 生成）
  - `评审关系  rev-hello → W1 · W2`（按 item.reviewers 聚合）
- **依赖箭头全部移除**：画布不再画任何跨卡曲线，卡片之间没有交叉线；
- **拓扑面板同步**：工单胶囊保留 `评 rev` 角标，并在图例下新增 `评审关系 rev → W1 · W2` 摘要（与同伴消息胶囊并列）；
- 关系行是文字 chip：可悬停看全量（title），窄屏自动换行，不依赖坐标或缩放。

真实 Host 截图：`docs/evidence/dashboard/relations-strips-live.png`（流程图底部「评审关系 rev → S」、拓扑「评审关系 rev → S」、卡片角标同屏）。

## 2.8 活跃 Agent 标注与高亮（v1.13.0）

原先「谁真的在跑」只能靠模糊的绿点/状态文字判断。现在引擎快照里的 `team.members[].status` 被直接映射为视觉层级：

- **Hero 新增「活跃」统计**：已批准 / 参与者 / **活跃** / 待处理 四格，活跃=status `running` 的成员数；
- **拓扑成员列高亮**：running 列加绿色描边、浅绿底色、呼吸绿点与 `运行中` 胶囊；inactive 列整体降至 74% 不透明度并弱化（hover 恢复），一眼区分"在干活"与"待命"；
- **流程图卡片**：执行者行前置**绿色 live 点**（带脉冲），owner 正在运行的卡片立即被识别；
- **面板 hint**：`成员 3 · 工作项 4 · 活跃 2 · 空闲 1 人`；
- **降级**：`prefers-reduced-motion` 下关闭呼吸动画；颜色全部来自 success token。

预览：`docs/evidence/dashboard/active-agents-preview.png`（活跃 3、两个 running 列高亮、inactive 列变灰、卡片 live 点）。

## 2.9 六人以上拓扑的密排优化（v1.14.0）

用户实测 6 成员 / 8 工单时，成员列头部被裁切：长名字 +「运行中」+「fresh」挤在一行，`portrait-engineer 运…` 直接被切；同时每列被拉伸到等高，空列形成大片空白。

- **列宽 218–330px**（原 160–250），长名字可读；
- **列头允许换行**：名字 `flex:1 1 auto` 独占省略号，`运行中` 胶囊 `flex:none` 不被压扁；名字过长时胶囊自动换到第二行而不是一起被裁；
- **精简列头信息**：`fresh/fork` 上下文徽章从列头移除，移入悬停 title（`名字 · 状态 · 上下文`），列头更安静；
- **列按内容收紧**：`.atw-topo-grid{align-items:flex-start}`，空列只占标题+「暂无负责项」，不再被撑成同高大方框；
- **工单胶囊**：评审角标 `max-width:62%` + 省略号，长 reviewer 名不会撑破胶囊；
- 真实数据预览（6 成员 / 8 工单 / 空闲 2 人）：`docs/evidence/dashboard/topology-6members-preview.png`。

## 2.10 事件流独占整行（v1.15.0）

事件流原来和门禁、升级挤在 1/3 列里：过滤胶囊换行成三排，事件行只剩单行截断，时间/类型/详情/actor 挤在一起。现在事件流有自己的一整行：

- **独占一行**：事件流从 `.atw-lower` 三列中移出，成 `.atw-events-row` 全宽行；门禁 + 升级改为两列在下；
- **过滤条一行**：全宽后 全部/评审/升级/修复/交付 胶囊单行右对齐，不再换行；
- **事件行改成日志布局**：`grid-template-columns:66px 108px minmax(0,1fr) max-content`，时间、类型、详情、actor 四列对齐；详情支持两行截断（hover 看全文）；
- **去掉逐行卡片边框**：改成分隔线列表（`border-bottom:1px hairline`，最后一行无边框），更像日志流、视觉更安静；
- **类型完整显示**：`review/submitted` / `item/reported` 不再被截成 `review/submitt…`；
- 面板高度 460px，30 条事件内部滚动。

预览：`docs/evidence/dashboard/events-row-preview.png`（全宽、单行过滤、四列对齐、分隔线）。
